# コミットグラフ

ブランチも、マージも、オクトパスマージも、ライトでもダークでもきちんと描かれます。
描画はウィンドウ方式なので、10 万コミットのリポジトリでも 100 コミットのリポジトリと
同じようにスクロールします。

|---|---|

## 動き回る

- <kbd>↑</kbd> <kbd>↓</kbd>（または <kbd>j</kbd> <kbd>k</kbd>）で選択を移動します。
- <kbd>⌘</kbd>/<kbd>Ctrl</kbd> + クリックで、いま選択中のコミットを起点にコミットを
  **複数選択** に出し入れし、<kbd>⇧</kbd> + クリックで範囲を選びます。複数を選んだ
  状態でそのどれかを右クリックすれば、現在のブランチへまとめてチェリーピックしたり、
  1 つにまとめたパッチを書き出したり、SHA をコピーしたりできます。
- **スカッシュ** はこのメニューに常に表示されますが、実行できるのは選択が現在の ブランチの先端と、その直下のコミットを飛ばさず含むときだけです — 最も古い コミットの親へのソフトリセットだからです。間に挟まるスタッシュ行は関係ありません。 それ以外ではグレー表示になり、ホバーすると理由が出ます。よくあるのは、チェック アウトしていないブランチのコミットを選んだ場合で、先にそのブランチをチェックアウト します。もっと下のコミットには [インタラクティブリベース](rebase.md) を使います。リベースと同じく、コミットフックは実行されません。コミットはすでに存在しており、フックが失敗してブランチが中途半端にリセットされたまま残ることもありません。
- **直近のフェッチやプル** で届いたコミットには、新着の印が付きます。チェックアウト中の
  ブランチにまだ入っていないものは、プルで取り込まれるまで少し半透明のままです。
- コミットを右クリックすると **修正**、**取り消し**、**コミットへリセット…**、
  **GitHub で見る** のほか、チェックアウト、チェリーピック、リバート、ブランチ、
  タグ、コピーが使えます。危険な操作は表示されたまま無効になります。

## 見たいものだけを見る

- **グラフのフォーカス**は、履歴をどこまで描くかを決めます。設定 → テーマ →
  **グラフ**、またはグラフのヘッダーにある歯車メニューから。*すべて*は全部を描き、
  *直線的な履歴*（first-parent）は幹だけを残し、*マージ済みブランチを隠す*は幹と
  まだマージされていないブランチを残し、*ソロモード*は自分のブランチ、スター付きの
  ブランチ、既定のブランチを残します。

  絞り込むのはログが読み込み済みの範囲だけです。*マージ済みブランチを隠す*は
  「現在のブランチに含まれているか」という git 自身の答えに従うため、ブランチを
  切り替えると隠れるものも変わります。また、タグや判別できない参照がまだ指している
  コミットは残します——削除されたブランチが残すのがまさにそれです。*直線的な履歴*
  と*ソロモード*はもっと大雑把で、隠したコミットの上にあるタグやスタッシュは一緒に
  消えます。

- **パスで絞り込む**: ファイルやフォルダを右クリック → *このパスでグラフを絞り込む*
  を選べば、それに触れたコミットだけが灯ります。

![1 つのパスに絞り込まれたグラフ](../../screenshots/graph-path-filter.webp)

- **列**: ブランチ、メッセージ、作者、日付、SHA、署名、デプロイの各列を表示・非表示・
  リサイズ・並べ替えできます。
- **スタイル**: 設定 → テーマ → **グラフ** — レーンの配色（組み込み 8 種、カスタム、
  AI 生成）、角の形、行の密度、線の太さを、ミニグラフのライブプレビュー付きで。

![ライブプレビュー付きのグラフスタイル設定](../../screenshots/settings-graph.webp)

## 日付の区切り

長い履歴をたどるとき、知りたいのはコミットの正確な時刻であることはまずありません
——それは日付列が答えます。知りたいのは「いまだいたいどのあたりか」です。日付の区切り
がそれに答えます。グラフを横切る細い線と、その右端にある相対的なラベルが、ある期間の
履歴が終わり、より古い期間が始まる場所を示します。

期間はさかのぼるほど粗くなります——今日、昨日、数日、1週間、数週間、数か月、数年。
そこが肝心です。暦日が変わるたびに線を引けば、活発なリポジトリではほぼ全コミットの下に
現れ、静かなリポジトリではどこにも現れません。

![グラフ内で履歴の期間を示す日付の区切り](../../screenshots/graph-date-dividers.webp)

区切りは、その期間の最後の行の**下**に置かれ、閉じた期間の名前を持ちます。つまり自分
より上の行を説明しています。画面のいちばん下の行には付きません——その期間は、まだ読み
込まれていないコミットへ続いているかもしれないからです。

限界について。コミットは `--date-order` で並ぶため、マージはそれが取り込んだコミット
より上に来ます。落ちた期間より新しい行は、新しい期間を開くのではなくその期間に加わり
ます——区切りは常に新しいものから古いものへ進みます。未コミットの変更の行とスタッシュ
は飛ばされます。その日付は履歴上の位置ではないからです。設定項目はなく、区切りは常に
表示されます。

## コミットの詳細

コミットを選ぶと、変更されたファイル（ツリー表示またはフラット表示）、作者、SHA、
共著者、そして署名が表示されます。`#123` の参照や `@mentions` は、あなたのホストへ
自動でリンクされます。

ファイル一覧の上には**変更サマリー**があり、単一の合計ではなくコミットを種類ごとに
分解して見せます — *5 件変更*、*1 件追加*、*1 件削除*、そしてコミットに含まれる場合は
*リネーム*と*競合*。それぞれの色は下の行のステータス記号や、折りたたんだフォルダーの
カウントバッジと揃えてあるので、同じ色はパネルのどこでも同じ意味になります。ファイルの
ない種類は完全に省かれるため、ふつうの編集では 5 つではなく 1 つだけ並びます。サマリーに
カーソルを重ねると「*n* 件のファイルが変更」という素の合計が出ます。

![コミットのファイル一覧の上に出る変更サマリー: 6 件変更、2 件追加、1 件削除、1 件リネーム](../../screenshots/change-summary.webp)

あえて教えないことが 2 つあります。数えるのは**行ではなくファイル**です。1 文字の修正も
全面的な書き直しも同じ *1 件変更* と読めます。実際の増減は差分そのものを見てください。
また、フィルターや検索で絞り込んだ一部ではなく、コミット内のすべてのファイルを数えます。

同じサマリーはステージング パネルとスタッシュのファイル一覧の先頭にも出ます。
ステージング パネルでは追跡外のファイルも追加として数えるので、*追加* は「ステージ済み」
ではなく「直前のコミットになかった」という意味になります。

ファイル一覧はいつもの操作で複数選択できます（<kbd>⌘</kbd>/<kbd>Ctrl</kbd>+クリック、<kbd>⇧</kbd>+クリック、<kbd>⇧</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd>）。選択範囲を右クリック
→ *{n} 件のファイルを作業ツリーへ復元* で、このコミット時点そのままの内容を持ってきます。1 回の確認のあと作業コピーを上書きし、HEAD
にもインデックスにも触れません。
