# 시작하기

Gitcito는 폴더를 열어 그 히스토리를 보여 줘요. 당신이 요청하기 전에는 저장소에
아무것도 쓰지 않아요.

![아직 커밋이 없는 갓 연 저장소](../../screenshots/empty-repo.webp)

## 저장소 열기

- 창 위로 **폴더를 끌어다 놓거나**, 시작 화면의 **저장소 열기** 를 쓰세요.
- URL 이나 호스트에서 바로 **클론** 하세요 — 거대한 저장소를 빠르게 클론하는
  옵션은 [클론하기](cloning.md)를 보세요.
- 터미널에서 `gitcito .` 를 실행하면 실행 중인 앱에서 현재 폴더가 열려요 —
  [명령줄](cli.md)을 보세요.
- 아직 Git 저장소가 아닌 폴더도 열리며, 초기화할지 물어봐요.

## 세 개의 창

| 창 | 담고 있는 것 |
|---|---|
| 왼쪽 | 브랜치, 원격, 태그, 스태시, 워크트리 — 그리고 작업 트리를 위한 **파일** 탭 |
| 가운데 | 커밋 그래프, 그리고 거기서 선택한 것 |
| 오른쪽 | 커밋 작성기, 또는 선택한 커밋의 상세 |

## 나머지 전부를 찾는 법

길은 두 갈래지만, 도착지는 같아요.

- **`⌘K`** (`Ctrl+K`) — 명령 팔레트. 원하는 것을 입력하세요. 브랜치, 커밋, 파일로
  바로 이동하기도 해요.
- 툴바의 **도구** — 같은 저장소 범위의 묶음을 메뉴로 보여 줘요. 잘 안 쓰는 것들은
  그룹으로 접어 두어 읽기 좋게 유지해요.

![도구 메뉴: 자주 쓰는 도구가 먼저, 나머지는 그룹으로](../../screenshots/tools-menu.webp)

액션 바는 버튼을 **창**의 가운데에 둡니다. 저장소 이름과 검색 상자 사이의 빈 공간 가운데가 아니므로, 이름 길이가 전혀 다른 저장소를 오가도 버튼은 같은 자리에 머무릅니다. 저장소 이름과 브랜치 이름은 줄이지 않고 그대로 보여 주며, 바의 나머지를 위협할 만큼 긴 이름만 줄임표로 잘리고 전체 이름은 버튼 툴팁에 담깁니다.

공간은 그 중심에서 바깥으로 재며, 그것이 중심을 지키는 값입니다. 창이 좁아지거나 저장소 이름이 아주 길면 바는 밀려나는 대신 자리를 내놓습니다. 가장 먼저 내놓는 것은 검색 필드로, 상자를 돋보기로 바꿉니다. 눌러서 검색할 수 있고, 필터가 걸려 있는 동안에는 열린 채로 남습니다. 그다음 들어가지 않는 버튼이 원래 순서와 하위 메뉴를 유지한 채 바 끝의 **더 보기** 메뉴로 접힙니다. 창을 넓히면 다시 나옵니다.

![좁은 창의 액션 바: 검색은 돋보기로 접히고, 바의 끝은 ‘더 보기’로 들어갔으며, 버튼은 여전히 가운데에 있다](../../screenshots/toolbar-narrow.webp)

한쪽으로 갈 수 있는 곳은 다른 쪽으로도 갈 수 있어요. 그러니 고급 사용자만 찾을
수 있는 것은 없어요.

## 첫 커밋

1. 파일을 편집하세요. **스테이징 안 됨** 아래에 나타나요.
2. 스테이징하세요 — 파일 전체, 헝크 하나, 또는 [줄 단위로](staging.md).
3. 메시지를 쓰고 **커밋** 을 누르세요.

Gitcito의 나머지는 전부 선택 사항이에요.
