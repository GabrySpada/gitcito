# 提交图

分支、合并以及章鱼式合并都被规规矩矩地画了出来，浅色深色皆可。渲染是按窗口进行的，所以一个有十万个提交的仓库，滚动起来和只有一百个提交的一样顺。

## 四处走动

- <kbd>↑</kbd> <kbd>↓</kbd>（或 <kbd>j</kbd> <kbd>k</kbd>）移动选中项。
- <kbd>⌘</kbd>／<kbd>Ctrl</kbd>+点击从当前已选中的提交开始，把一个提交加入或移出**多选**；<kbd>⇧</kbd>+点击选取一个区间。选中若干个之后，在其中一个上右键，即可把它们拣选（cherry-pick）到当前分支上、导出一份合并后的补丁，或者复制它们的 SHA。
- 菜单里始终有**压缩（squash）**，但只有当所选内容是当前分支的顶端及其正下方、中间不跳过任何提交时才能执行——它的做法是软重置到最旧那个提交的父提交。夹在中间的储藏行不影响。否则该项会变灰，悬停即可看到原因；最常见的是选中了未检出分支上的提交，先检出那个分支即可。要压缩更靠下的提交，请用[交互式变基](rebase.md)。和变基一样，不会运行提交钩子：这些提交本来就已存在，钩子失败也不会再让分支停在重置了一半的状态。
- 在你**最近一次获取或拉取**中到达的提交会被标为新提交。尚未进入当前检出分支的那些会
  略微半透明，直到一次拉取把它们带进来。
- 右键一个提交，可以看到**修补**、**撤销**、**重置到此提交…**和**在 GitHub 上查看**，外加检出、拣选、还原、建分支、打标签和复制。不安全的操作保持可见，但会被禁用。

## 让它只显示你想看的

- **提交图聚焦**决定画出多少历史——设置 → 主题 → **提交图**，或提交图表头的齿轮
  菜单。*全部*画出所有内容；*线性历史*（第一父提交）只留下主干；*隐藏已合并分支*
  保留主干加上尚未合并的分支；*独奏模式*保留你的分支、加星的分支和默认分支。

  它只过滤日志已经加载的内容。*隐藏已合并分支*依赖 git 自己对“是否已包含在当前
  分支”的判断，所以切换分支会改变隐藏的内容——而且它会保留仍被标签或它认不出的
  引用指向的每个提交，这正是被删除的分支留下的东西。*线性历史*和*独奏模式*更粗
  暴：位于它们隐藏的提交上的标签或贮藏会一起消失。

- **按路径筛选**：右键点击一个文件或文件夹 → *按此路径筛选图*，于是只有改动过它的提交还亮着。

![被筛选到只剩一条路径的图](../../screenshots/graph-path-filter.webp)

- **列**：分支、消息、作者、日期、SHA、签名和部署这几列都可以显示、隐藏、调整宽度和重新排序。
- **样式**：设置 → 主题 → **图**——泳道配色（8 套内置、自定义，或由 AI 生成）、拐角样式、行密度和线条粗细，并带一个实时的迷你图预览。

![带实时预览的图样式设置](../../screenshots/settings-graph.webp)

## 日期分隔线

翻阅一段很长的历史时，你想知道的几乎从来不是某次提交的准确时间——那由日期列回答。
你想知道的是“我大概到哪儿了”。日期分隔线回答的正是这个问题：一条横贯图谱的细线，右端
带一个相对时间标签，标出一段历史在哪里结束、更早的一段从哪里开始。

区间会随着回溯而变粗——今天、昨天、几天、一周、几周、几个月、几年。这正是要点：若每次
跨过日历日就画一条线，活跃仓库里几乎每一行下面都会有一条，而安静的仓库里一条也没有。

![图谱中标出历史区间的日期分隔线](../../screenshots/graph-date-dividers.webp)

分隔线位于所属区间最后一行的**下方**，标注的是它所结束的那个区间，因此它描述的是上方
的行。屏幕最底下的一行不会有分隔线——它所在的区间可能还延续到尚未加载的提交里。

它的限度。提交按 `--date-order` 排列，合并会排在它所合并的提交之上；因此比所在区间更新
的行会并入该区间，而不是另开一个——分隔线始终由新到旧。未提交更改行和贮藏会被跳过，
因为它们的日期并不代表它们在历史中的位置。这里没有开关：分隔线始终显示。

## 提交详情

选中一个提交会显示它改动的文件（按树状或平铺）、作者、SHA、共同作者，以及它的签名。`#123` 引用和 `@mentions` 会自动链接到你的托管方。

文件列表上方有一条**改动摘要**，它把提交按类型拆开，而不是只给一个总数 —— *5 个修改*、*1 个新增*、*1 个删除*，提交里有的话还会加上*重命名*和*冲突*。每一项的颜色都和下方行的状态标记、折叠文件夹上的计数徽标一致，所以同一种颜色在整个面板里表示同一件事。没有文件的类型会被完全略去，因此一次普通的修改只显示一项，而不是五项。把鼠标停在摘要上，可以看到"*n* 个文件有改动"的朴素总数。

![提交文件列表上方的改动摘要：6 个修改、2 个新增、1 个删除、1 个重命名](../../screenshots/change-summary.webp)

有两件事它刻意不告诉你。它数的是**文件，不是行数**：改一个字符和整篇重写都读作 *1 个修改*；改动到底有多大，要看 diff 本身。而且它数的是这个提交里的全部文件，不是符合当前筛选或搜索的那一部分。

暂存面板和贮藏的文件列表顶部也是同一条摘要。在暂存面板里，未跟踪的文件也算作新增，所以*新增*的意思是"上一个提交里没有"，而不是"已经暂存"。

文件列表可以用惯常的手势多选（<kbd>⌘</kbd>/<kbd>Ctrl</kbd>+点击、<kbd>⇧</kbd>+点击、<kbd>⇧</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd>）。在选中项上右键
→ *将 {n} 个文件恢复到工作树*，会拿到这些文件在该提交时的原样：一次确认后覆盖工作副本，不动 HEAD，也不动索引。
